# 历史检索、调试隔离与隐私（0.2.1）

## 启用与数据

先完整备份配置及插件数据目录（含身份密钥、遗忘标记、Markdown、SQLite/WAL、图片和隐私授权文件），在独立测试实例验证。`enabled`、`context_policy_enabled`、`embedding_enabled` 等可选开关仍默认关闭。历史归档读取 AstrBot `/AstrBot/data/data_v4.db`，不修改原聊天数据库，不把旧聊天自动升级为正式记忆。归档正文会遮蔽可识别凭据，因此并非逐字无损的凭据备份。

启用上下文策略后，历史工具只检索可见 user/assistant 正文；工具结果和隐藏推理不作为普通聊天搜索结果。启用现有 Embedding Provider 后，增加语义召回，失败保留词法检索，不调用 LLM 摘要。身份、域、调试标签和隐私过滤在索引前与返回前检查。

## 时间与覆盖范围

`companion_archive_search` 支持最早交流意图，并返回可访问会话的覆盖范围。单条消息没有可信时间就明确未知；会话创建时间只是范围参考，归档入库时间不能冒充聊天发生时间。关键词没命中不证明原记录不存在。最早意图是规则判断，可能误判，没有任意日期筛选或分页保证。

## 索引成本

每块最多 600 字符，步长 520；每轮最多 16 块。历史索引每日上限 100 次请求、100000 UTF-8 字节，并受现有全局 Embedding 预算限制。每日边界为北京时间，首次建索引可能跨日完成。检索最多 3 条、每条 500 字符，相似度阈值 0.65；查询超时回退，缓存最长一小时。字节预算不是供应商计费 Token；不要将单价直接乘字节数。不会为已有数据强制全库重建。当前可见向量逐条比较，大库应先基准测试。

## 调试记录

归档具有 `archive_labels` 和 `label_signatures`，已标记的调试/错例不参与普通、最早或语义检索。标签继承按完整消息 payload 的 HMAC 及同一 agent/域/会话匹配，不能按空正文或昵称匹配。公开包不含任何真实标签数据，也尚未提供分类管理命令或自动分类器；已有历史分类需要单独审核的维护流程，勿在运行中用第二个写进程改库。原文不会因标签而删除。

## 敏感内容与逐条授权

本地规则分为公开资料(0)、普通内容(1)、敏感内容(2)、凭据(3)。敏感记录默认只对信息主体可见且不发到外部向量服务；凭据不能通过授权分享。图片默认保守保护，不做 OCR 或云端识图来判断隐私。规则可能漏判隐含敏感信息，也可能误判，不能代替人工判断。

命令必须一条消息一条完整命令；将示例 ID 替换为你有权限的真实记录编号：

```text
/fmem privacy status archive:123
/fmem privacy restrict archive:123
/fmem privacy grant archive:123 peer
/fmem privacy revoke archive:123 peer
/fmem privacy status memory:<记忆ID>
/fmem privacy restrict image:<图片ID>
```

仅记录的信息主体可操作；`owner` 和 `peer` 必须已处于该条的基础可读域，授权绝不扩大身份 ACL，也不开放其他访客或其他 Bot 的数据。`owner` 当前选择配置中的首位主人，多主人精细选择尚未实现。敏感授权后仍不向外部 Embedding 服务发送。策略以 HMAC 标识持久化到 `agent_memory/privacy_policy.json`，不存正文，文件权限 0600（Windows ACL 需额外核对）。

## 边界与回滚

这是应用层隔离，不是进程/文件系统沙箱；拥有文件或其他管理工具权限的插件仍可能读取数据。正式记忆遗忘不会自动清除所有历史原文、备份或已发送给外部服务的内容。上下文缩短与 Token 节省依赖数据和参数，不保证固定比例或无限对话。

回滚时停 AstrBot 的写入，先保留当前全量副本，再恢复同一时点的旧源码、配置和完整插件数据；不要只换旧代码让其忽略新隐私策略。恢复前检查身份配置和隐私授权，验证 SQLite 完整性、跨用户拒绝和旧数据可读后再启动。不要重启 QQ 协议端。公开版不支持自动重命名非 bot1/bot2 的生产数据。
