# 0.2.1 升级边界

本版内部 Agent 路由统一为 `bot1`、`bot2`，相关配置键和可信 peer 角色命名也更新。它影响路径、签名与身份，不只是显示名。

新用户用空插件数据目录，填写自己的身份，在独立实例逐项验证。旧版用户：

1. **更新源码和 schema 之前**停用插件并确认写入退出，完整备份旧源码、配置和插件数据根，包括身份密钥、遗忘记录、Markdown、SQLite/WAL/SHM、向量库、图片与档案（如有）。
2. 本版**没有自动身份迁移工具**。先在另一实例测试，不要覆盖旧数据后期望自动改名。schema 加载可能替换旧配置键，因此旧配置必须提前保存。
3. 存储中出现不支持的 Agent 标签时，引擎在创建密钥、写数据库和恢复 Markdown 前拒绝初始化。普通聊天不重置，记忆不可用；日志指向本说明。
4. 不要手工替换数据库字符串、重命名目录、改 header 或重建身份密钥。ACL、HMAC 来源、引用、图谱、遗忘摘要和向量需要一致迁移。
5. 真正迁移需另行设计、验证离线全结构转换；不能可靠验证就继续使用旧版。

回退先停写、保存当前完整副本，保留更新后新增记录，再恢复升级前匹配的代码、配置与完整插件数据。不要覆盖 AstrBot 原聊天库或人格，也不要仅降级 Python 文件后继续写新格式数据。

公开包不包含任何私人生产环境的回滚脚本、连接资料或路径。
